# US-15.1 — Docker production packaging

The repository provides multi-stage production images for the Spring Boot API
and the Vite SPA. The backend image runs as an unprivileged user, while the
frontend image serves the minified Vite build through Nginx. Nginx proxies
`/api/` to the internal backend service, so the browser uses the same public
origin in Docker.

## Run the complete system

1. Install Docker Engine with the Compose plugin.
2. Copy `.env.example` to `.env` at the repository root and set strong values
   for `MYSQL_PASSWORD`, `MYSQL_ROOT_PASSWORD`, and `JWT_SECRET`. Keep `.env`
   out of source control.
3. Start all services:

```powershell
docker compose up --build -d
```

Open `http://localhost:8080`. The public API is available through the frontend
proxy at `http://localhost:8080/api/v1/health`.

## Verify and stop

```powershell
docker compose ps
docker compose logs --follow backend
curl.exe http://localhost:8080/api/v1/health
docker compose down
```

Use `docker compose down -v` only when intentionally deleting the persistent
MySQL and uploaded-file volumes.

## Production image characteristics

- Backend: Maven build stage, Java 21 JRE runtime stage, no root process.
- Frontend: locked `npm ci`, Vite production minification, Nginx static server,
  immutable caching for hashed assets and SPA route fallback.
- Compose: MySQL is private to the Docker network; only the frontend port is
  published. Database and product uploads use named persistent volumes.
- Health checks wait for MySQL, backend database readiness and the frontend
  static server before dependent services continue.

This workstation does not have Docker installed, so `docker compose up` must
be run on a Docker-capable machine or CI as the final image-runtime check.
