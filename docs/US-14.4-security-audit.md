# US-14.4 security audit

## Scope and controls

- User text is bounded with Jakarta Bean Validation. Product, category and review text is returned as JSON and rendered by React's default text escaping; no `dangerouslySetInnerHTML`/`innerHTML` is used. Brand/category image URLs accept only `http(s)` or single-slash local paths through `SafeUrlValidator`.
- Repository queries use Spring Data derived queries or JPQL with named parameters. The only JDBC statement in production code is the constant `SELECT 1` database health probe; no user input is concatenated into SQL.
- Order detail/cancellation, checkout addresses, profile and notification lookups are scoped to the authenticated user. Admin routes are role-checked by the JWT interceptor, which now fails closed when its authenticator is unavailable.
- JWT bearer authentication is stateless and is not accepted from cookies. CORS credentials are disabled, which prevents ambient-cookie CSRF; production origins must be supplied through `CORS_ALLOWED_ORIGINS`.
- API responses receive `nosniff`, frame-deny, referrer, permissions, CSP and no-store headers. Login endpoints are throttled at five failed attempts per source address and endpoint per minute and return `429` with `Retry-After`.
- Uploaded-file deletion is restricted to generated UUID filenames inside the configured upload directory.

## Verification

The backend test suite covers the security filters and existing login, authorization and ownership integration tests. A frontend regression test verifies that a review containing an HTML payload remains text and does not create an event-handler element.
