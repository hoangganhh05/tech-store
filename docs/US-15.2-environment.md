# US-15.2 — Production environment configuration

Production settings are supplied from the runtime environment; no database
password, JWT key or SMTP credential belongs in source control. The root
`.env.example` lists every Backend and Docker Compose variable. The frontend
uses [`.env.production.example`](../frontend/.env.production.example) only for
public, build-time `VITE_*` values.

## Prepare production settings

1. Copy `.env.example` to a private deployment secret store or a local `.env`
   file that will never be committed.
2. Generate a unique production signing key:

```powershell
.\scripts\new-production-jwt-secret.ps1
```

3. Put that output in `JWT_SECRET`, configure strong and different
   `MYSQL_PASSWORD` / `MYSQL_ROOT_PASSWORD`, and set the real SMTP credentials.
4. Set `CORS_ALLOWED_ORIGINS` and `PASSWORD_RESET_FRONTEND_URL` to the exact
   public HTTPS origin(s). Do not use `*`.

The `prod` profile refuses the known development JWT secret, wildcard origins
and non-HTTPS public URLs. `localhost` over HTTP is allowed only for the
isolated Docker Compose smoke test.

## Runtime separation

| Environment | Profile | Configuration source |
| --- | --- | --- |
| Local development | `dev` | Terminal variables or an untracked local `.env` |
| Automated tests | `test` | `application-test.yml` and CI environment |
| Production | `prod` | Deployment secret store / Docker Compose `.env` |

Never commit `.env`, `.env.production`, generated keys, database credentials or
SMTP passwords. The repository ignores these files while retaining the example
templates.
