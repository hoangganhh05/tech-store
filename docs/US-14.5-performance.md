# US-14.5 performance verification

## Changes under test

- `V25__add_storefront_query_indexes.sql` adds composite indexes for active products, category/brand filters, variants, images, inventory sales aggregation and category navigation.
- Storefront product repository methods use `@EntityGraph(brand, category)` so mapping a list does not lazily load those associations one product at a time.
- Category/brand/search predicates are evaluated by the database. Variants, images, sales and effective prices are loaded in batch for the selected product set.
- Search input remains accent-insensitive; the H2 test profile has a fallback because H2 does not use the same accent-insensitive collation as MySQL.

## Automated verification

Run the following checks from the repository root:

```powershell
Set-Location backend
.\mvnw.cmd -q '-Dtest=StorefrontProductServiceImplTest,StorefrontIntegrationTest' test
```

`StorefrontProductServiceImplTest` verifies that a 25-product response uses one batch call each for variants, images and sales rather than one call per product. `StorefrontIntegrationTest` covers the public list, filter, sort, pagination and accent-insensitive search contracts. `StorefrontPerformanceTest` warms a 100-product dataset, measures 30 list and search requests, and guards both p95 latencies below 500 ms (application startup is excluded).

Latest local verification (H2 test profile, 100 products, 30 measured requests after 10 warm-ups): list p95 **50 ms**, search p95 **84 ms**.

## QA benchmark procedure (T-14.5.3)

1. Seed the same medium dataset in a test/staging database (at least 100 active products, 2–3 variants and one image per product).
2. Warm the application with 10 requests, then measure 100 requests at concurrency 10 for both endpoints:
   - `GET /api/v1/products?page=0&size=20`
   - `GET /api/v1/products/search?q=phone`
3. Record p50/p95/p99 and database query count before and after this branch. Exclude application startup and report the database engine, dataset size and concurrency with the results.
4. Acceptance target: p95 is below the agreed 500 ms threshold on the medium dataset, and the product response does not show an N+1 increase as product count grows.

For a repeatable command-line run, use an HTTP load tool available in the environment (for example `hey` or JMeter) and attach its output to the US-14.5 QA evidence. The automated tests above are the regression gate; the benchmark is intentionally environment-specific.
