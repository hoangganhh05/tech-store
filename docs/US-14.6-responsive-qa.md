# US-14.6 responsive storefront QA

## Breakpoints

Verify the main storefront routes at these viewport sizes:

| Profile | Viewport |
| --- | --- |
| Small mobile | 320 × 568 |
| Mobile | 390 × 844 |
| Tablet | 768 × 1024 |
| Desktop | 1280 × 800 |

Routes in scope: `/`, `/products`, `/products/:id`, `/cart`, and `/checkout`.

## Acceptance checklist

- Header navigation, search, account actions and cart remain usable without horizontal page overflow. Navigation can be scrolled horizontally on small screens.
- Home hero, category tiles and product grids reflow from one column on mobile to tablet/desktop columns.
- Product detail gallery scales to the viewport, thumbnails remain horizontally scrollable, and long names/specifications wrap instead of covering controls.
- Color/storage selectors, quantity controls, wishlist and add-to-cart/buy-now actions have touch-sized targets and remain reachable on mobile.
- Cart content stays within the viewport (the table has touch-friendly horizontal scrolling for dense columns); item labels, chips and totals wrap cleanly.
- Checkout address cards, payment choices, voucher input and order review actions stack vertically on mobile, with full-width primary actions.
- No fixed-width element obscures content at any listed viewport; dialogs and alerts remain dismissible.

## Regression commands

```powershell
Set-Location frontend
npm run typecheck
npm run lint
npm test -- --run
```

For manual QA, use browser device emulation at each viewport, exercise variant selection, quantity changes, add-to-cart, address selection, payment selection, voucher entry and order placement. Record screenshots and any p95 interaction issues with the US-14.6 evidence.
